Detailed Description

Point d'entrée d’AODjustify : vérifications E/S, orchestration du parsing et de la justification.

Chaîne de traitement (correspond aux sections du code) :

  1. Arguments : attend exactement 2 arguments utilisateur — M (Mu, entier > 0) et un préfixe de fichier.
  2. Fichier d’entrée : construit <prefix>.in, ouvre en lecture (O_RDONLY | O_NONBLOCK), récupère la taille via getSize(), et valide le type/encodage (texte ISO-8859-1) via fileBI() (message d’erreur mis dans buffer).
  3. Lecture/Parsing :
    • ouvre <prefix>.out en écriture binaire ;
    • crée le contexte mmap via psopen(fd, size, Mu) ;
    • pré-calcule le tableau cubes[0..Mu] avec i^3 en 64 bits puis saturation sur LLONG_MAX.
    • boucle par paragraphe : nextPG() → getPG() ; entre paragraphes, écrit une ligne vide (‘’
      ').
  4. **Justification** : pour chaque paragraphe, appellesetPG(&pg, Mu, out, cubes)(DP + écriture des lignes). En cas d’échec du programme, le fichier de sortie en cours est **supprimé** via @reffreeALL.
  5. **Nettoyage & résultat** :freeALL(ps, out, cubes); affiche surstderrla norme totale sous la forme AODjustify CORRECT> <valeur>` puis retourne 0 en cas de succès (1 sinon).
Note
Noms de fichiers :
  • entrée : <prefix>.in
  • sortie : <prefix>.out

Returns
Code de retour : 0 si succès ; 1 en cas d'erreur (messages sur stderr).
  • Construit les chemins <prefix>.in et <prefix>.out.
  • Valide l’entrée (existence, taille, type/encodage ISO-8859-1).
  • Ouvre/mappe l’entrée, prépare la sortie.
  • Pré-calcule cubes[0..M] avec saturation sur LLONG_MAX.
  • Itère par paragraphe : nextPG() → getPG() → setPG() ; insère une ligne vide entre paragraphes.
  • En cas d’erreur getPG(), supprime le fichier de sortie en cours (remove(file_out)).
  • Agrège la norme totale (badness) et l’affiche sur stderr.

Un petit clin d'œil aux ancêtres : Badness représente la "mocheté" totale de notre justification. The lowest the badness is, the prettier the text will look!
